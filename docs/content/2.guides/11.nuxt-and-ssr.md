vccs renders complete SVG charts on the server. The first paint already shows axes, bars and lines, and hydration takes over without warnings or layout jumps.

## Install the module

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['vccs/nuxt'],
})
```

The module auto-imports every chart component. Add a prefix if your app already has a `Line` or `Area` component:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['vccs/nuxt'],
  vccs: { prefix: 'V' }, // <VBarChart>, <VLine>, ...
})
```

## How server rendering works

The server cannot measure the browser, so a responsive chart renders at an initial size and scales into its box with a `viewBox`. After mount the chart measures its box and lays out at the real size.

- A chart with numeric `width` and `height` renders exactly at that size.
- A chart with only `height` (the most common case) renders 640 px wide on the server and fills the container width in the browser.
- Without a size, the chart starts at 640 × 360 (or `640 / aspect` high when `aspect` is set).

Pick an initial size close to the real one to keep the first paint sharp:

```vue
<AreaChart :data="data" :height="250" :initial-dimension="{ width: 900, height: 250 }">
  <Area data-key="desktop" />
</AreaChart>
```

The shadcn-vue `ChartContainer` uses a 16:9 box by default, which matches the default initial size.

## What vccs does for you

- **Same first render on server and client.** Every chart item registers before any geometry renders, regardless of the order you declare children in. A `<Line>` declared before a `<Bar>` still gets the bar's category padding on the first render.
- **No entrance replay.** Content that came from the server does not animate in again after hydration. Charts that mount only in the browser still animate in.
- **No text measurement during hydration.** Tick sizes are measured after mount, then the layout settles.
- **Request isolation.** Generated ids use Vue's `useId()`, and no chart state lives in module scope.

## Client-only charts

You do not need `<ClientOnly>`. Use it only when the data itself exists only in the browser, for example from `localStorage`.
