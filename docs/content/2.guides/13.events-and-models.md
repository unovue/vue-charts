## Events

All callbacks are typed Vue events, so your editor completes their names and payloads.

```vue
<BarChart :data="data" @click="(state, event) => console.log(state.activeIndex)">
  <Bar data-key="desktop" @click="(entry, index, event) => select(entry.payload)" />
</BarChart>
```

| Component | Events | Payload |
|---|---|---|
| Charts | `click`, `mouseenter`, `mousemove`, `mouseleave`, `mousedown`, `mouseup`, `contextmenu`, `dblclick`, `touchstart`, `touchmove`, `touchend` | `(state: ChartPointerState, event)` |
| Series (`Bar`, `Line`, `Area`, `Scatter`, `Pie`, `Radar`, `RadialBar`, `Funnel`) | `click`, `mouseenter`, `mouseleave` | `(entry, index, event)` |
| Series | `animation-start`, `animation-end` | none |
| `Brush` | `change`, `drag-end` | `{ startIndex, endIndex }` |
| `Legend` | `click`, `mouseenter`, `mouseleave` | `(entry, index, event)` |

## v-model

Bind a model when the rest of your page needs to read or set chart state. Without a model, the chart manages the state itself.

### Brush range

```vue
<script setup lang="ts">
const from = ref(0)
const to = ref(29)
</script>

<template>
  <BarChart
    :data="data"
    :height="300"
  >
    <Bar data-key="desktop" />
    <Brush
      v-model:start-index="from"
      v-model:end-index="to"
    />
  </BarChart>
  <p>Showing rows {{ from }}–{{ to }}</p>
</template>
```

### Active tooltip point

Highlight the same row in a table and in the chart:

```vue
<script setup lang="ts">
const active = ref<number | null>(null)
</script>

<template>
  <LineChart
    :data="data"
    :height="300"
  >
    <Line data-key="desktop" />
    <Tooltip v-model:active-index="active" />
  </LineChart>
  <tr
    v-for="(row, i) in data"
    :key="row.date"
    :class="{ highlight: i === active }"
    @mouseenter="active = i"
  >
    ...
  </tr>
</template>
```

`null` hides the tooltip. If you omit `active-index`, the chart manages selection. If you supply it, including `null`, pointer, keyboard and sync events request a change through `update:activeIndex`. The displayed selection changes only when you accept that request.

In axis mode, the Tooltip index addresses a chart data position. In item mode, it addresses the keyboard order: series in registration order, then each series' data order. Treemap uses leaves in row order, Sankey uses nodes by column and height, and Sunburst uses depth-first order. These model indexes are numbers.

`Bar` and `Pie` also support `v-model:active-index`, using positions within their own series. A controlled chart-level Tooltip takes precedence over these series controls. Without a controlled Tooltip, each controlled series owns its active item and other series remain uncontrolled.

Multiple Tooltips share one selection and all receive change requests. The first registered Tooltip owns interaction settings (`shared`, `trigger`, `axis-id`, `default-index`, `active`); later Tooltips can set presentation options such as formatters, content, styles and cursors. Only one Tooltip in a chart may supply a controlled `active-index`.

An uncontrolled selection follows the same item through reorder and resize and clears when that item is removed or hidden. Controlled indexes address the current order. An invalid index shows no active target and requests `null` once for each distinct invalid input or target order.

### Hidden series

When `hidden` is bound, clicking a legend item shows or hides its series:

```vue
<script setup lang="ts">
const hidden = ref<string[]>([])
</script>

<template>
  <AreaChart
    :data="data"
    :height="300"
  >
    <Area data-key="desktop" />
    <Area data-key="mobile" />
    <Legend v-model:hidden="hidden" />
  </AreaChart>
</template>
```
