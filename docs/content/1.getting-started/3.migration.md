vccs 1.0 rebuilds every chart on a Vue model and settles the public API. Most apps need the
steps below; the tables after them list every change with what to do.

1. Install `vue@^3.5` and `motion-v@^2.4`.
2. Replace callback props with Vue events: `:onClick` → `@click`.
3. Use `v-model:active-index` (`number | null`) and `v-model:range` on `Brush`.
4. Remove `responsive` and sizing-only `ResponsiveContainer` wrappers; set `height` on the chart.
5. Import only public components, hooks and types; `useOffset` becomes `usePlotArea`.
6. Update CSS selectors to the `v-charts-` classes, and colors to the theming tokens.
7. Rename the props in [Renamed props and events](#renamed-props-and-events).

## Setup

| Change | What to do |
|---|---|
| Peer dependencies are `vue@^3.5` and `motion-v@^2.4`. | Update both. |
| Charts are responsive by default; the `responsive` prop is removed. | Remove `responsive`. Set numeric `width` and `height` for a fixed size, only `height` for full width. |
| `ResponsiveContainer` no longer injects `width`/`height` into its child. | Usually nothing: the chart fills the container. Remove the container if it only sized the chart. |
| The Nuxt module requires Nuxt 4 (`@nuxt/kit ^4.0.0`, `meta.compatibility` `>=4.0.0`). | Upgrade to Nuxt 4. Nuxt 3 is end-of-life and was never tested. |
| The Nuxt module option `vccs: { components: false }` is removed. | Remove the option. To opt out, remove the module. |
| `unplugin-vue-components` is no longer a peer dependency of vccs. | Nothing, unless you use `vccs/resolver`: then keep `unplugin-vue-components` in your own `devDependencies`. |

## Models and events

| Change | What to do |
|---|---|
| Active models use `number \| null`; supplied values control the display across Tooltip, Sparkline, Pie, Bar and cell charts. | Before: `<Bar :active-index="-1" data-key="value" />`. After: `<Bar v-model:active-index="active" data-key="value" />`, with `ref<number \| null>(null)`. Standalone charts use the same model; rejected requests leave the supplied selection unchanged. |
| Brush uses one nullable range model; supplied ranges are parent-controlled. | Before: `<Brush v-model:start-index="from" v-model:end-index="to" />`. After: `<Brush v-model:range="range" />`, with `ref<BrushStartEndIndex \| null>({ startIndex: 0, endIndex: 5 })`. `null` shows all rows and hides travellers. Finite bounds are floored, clamped and ordered. |
| Callback props (`:onClick`, `:onAnimationEnd`, `onChange` on Brush, …) are now Vue events. | Use `@click`, `@animation-end`, `@change`. JSX `onClick={…}` keeps working. |
| Treemap, Sankey and SunburstChart support keyboard activation; `node-click` can receive a `KeyboardEvent`. | Accept `MouseEvent \| KeyboardEvent` in explicitly typed handlers. Check `event instanceof MouseEvent` before reading pointer coordinates. |
| An uncontrolled Brush keeps its window when data updates; it no longer snaps back to the last row on every new array. | Nothing for most apps. Same row count keeps the window; rows added while the window ends at the last row shift it forward with the same width (a full window stays full); rows added elsewhere keep the positions; removed rows clamp it. A shifted or clamped window emits `update:range`. A controlled `v-model:range` is unchanged. |

## Exports and types

| Change | What to do |
|---|---|
| Internal contexts, payload searchers, path builders, `Global`, `*VueProps` and internal-only types are no longer root exports. | Before: `import { LineVueProps, getPath } from 'vccs'`. After: `import { Curve } from 'vccs'; import type { LineProps } from 'vccs'`. Use public components and hooks. |
| `useOffset` is removed from the public exports. | Before: `const { left, top } = useOffset().value`. After: `const { x, y } = usePlotArea().value`. |
| Public hooks retain their runtime nullability in strict declarations. | Before: `useActiveTooltipCoordinate().value.x`. After: `useActiveTooltipCoordinate().value?.x`. |
| Scatter payloads omit `tooltipPosition` when either coordinate is missing. | Guard `point.tooltipPosition` before reading its coordinates. |
| Every public `XxxProps` type is derived from its component and includes its events. `LineProps` no longer has `animateNewValues`; `FunnelProps` has `fill` and `class`; `CartesianAxisProps` no longer requires `scale`; `AreaProps`, `PieProps`, `BrushProps`, `LegendProps`, `CurveProps`, `DotProps`, `RectangleProps` and `SectorProps` now carry emits and SVG attributes. | Before: `defineProps<AreaProps>()` lost `@click`. After: the same type keeps `onClick` and `onUpdate:range`. Remove props the component never had. |
| `*PropsWithSVG` types are removed (`LinePropsWithSVG`, `FunnelPropsWithSVG`, `LegendPropsWithSVG`, `PiePropsWithSVG`, `RadialBarPropsWithSVG`, `RectanglePropsWithSVG`, `SectorPropsWithSVG`). | Before: `LinePropsWithSVG`. After: `LineProps`. |
| The trapezoid geometry type is renamed: `TrapezoidProps` → `TrapezoidItem`; `TrapezoidComponentProps` → `TrapezoidProps`. | `XxxProps` always means a component's props. Rename the imports. |
| `Point` has one definition, with an optional readonly `payload`. | Nothing, unless you built objects that must not have `payload`. |
| `TypedComponents<Row, Components>` requires its second parameter. | Before: `TypedComponents<Row>`. After: `TypedComponents<Row, typeof components>`. |
| Folder entry points such as `vccs/src/cartesian` or `@/shape` are gone. | Import from `vccs` only. |

## Props

| Change | What to do |
|---|---|
| Line and Area no longer accept internal geometry or active-point props: `points`, `path`, `baseLine`, `layout`, `left`, `top`, `width`, `height`, `animationId`, `activePoint`, `needClip`, `activeIndex`. | Before: `<Line data-key="value" :points="points" />`. After: `<Line data-key="value" />`. Set data, layout and dimensions on the chart; use the series slots to customize shapes. |
| Bar no longer accepts internal `needClip` or `id` props. Its `active-index` model remains supported. | Before: `<Bar data-key="value" id="bars" :need-clip="true" />`. After: `<Bar data-key="value" />`. Axis overflow settings determine clipping. |
| Legend no longer accepts `chartWidth`, `chartHeight` or `margin`. | Before: `<Legend :chart-width="500" :margin="margin" />`. After: `<Legend />`. Set dimensions and margin on the chart. |
| Label no longer accepts `parentViewBox` or `index`. | Before: `<Label :parent-view-box="box" :index="0" value="A" />`. After: `<Label :view-box="box" value="A" />`. Use a LabelList content slot when the item index is needed. |
| Categorical charts remove `to` and `throttleDelay`, and reject props from other chart families. | Before: `<BarChart :cx="100" :throttle-delay="50" />`. After: `<BarChart />`. Pie/Radar remove bar sizing props; RadialBar keeps them; Funnel removes both groups. These props had no effect. |
| Series animation defaults inherit from the chart; explicit item props still override them. | Before: `<BarChart><Bar data-key="value" :is-animation-active="false" /></BarChart>`. After: `<BarChart :is-animation-active="false"><Bar data-key="value" /></BarChart>`. |
| XAxis and YAxis now type orientation, axis type, padding and scale names. Presentation props (`tick`, `angle`, `label`, `name`, `stroke`, `tickSize`) are declared and forwarded. | Before: `<XAxis orientation="sideways" />`. After: `<XAxis orientation="top" :tick="false" :angle="-45" label="Day" />`. YAxis accepts `left` or `right`; padding accepts the axis-specific object, `gap` or `no-gap`. |
| The Brush `data` prop is removed. It was never read; Brush always uses the chart data. | Before: `<Brush :data="rows" />`. After: `<Brush />`; set `data` on the chart. |
| The chart `dataKey` prop is removed. It was never read. | Before: `<BarChart data-key="x">`. After: `<BarChart>`. The attribute now falls through as a plain attribute. |
| Line and Area `dot` and `activeDot` accept `boolean` or an options object, like Radar. A render function was never called and drew default dots. | Before: `<Line :dot="renderDot" />` (ignored). After: `<Line><template #dot="p">…</template></Line>`; the same for `#activeDot`. |

## Styling and colors

| Change | What to do |
|---|---|
| All classes use the `v-charts-` prefix in kebab case (`vcharts-surface` → `v-charts-surface`, `recharts-brush-traveller` → `v-charts-brush-traveller`, `v-charts-errorBar` → `v-charts-error-bar`); the unprefixed `xAxis`/`yAxis` classes are removed. | Update CSS selectors. |
| Default colors are CSS variables (`stroke="var(--v-charts-grid, #ccc)"`). | Replace selectors like `[stroke='#ccc']` with the tokens on the Theming page. |
| Default series colors use `--v-charts-series-1` through `--v-charts-series-8`. Bar and Scatter have a default fill. CalendarHeatmap defaults to blue. | Before: `<CalendarHeatmap :data="days" />` used green. After: `<CalendarHeatmap :data="days" color="#16a34a" />` keeps that color; set numbered tokens or explicit colors for other series. |
| `Bar` no longer defaults `strokeWidth` to `0`, so a `stroke` shows. React-style attributes such as `strokeWidth` and `fontSize` now reach the SVG as `stroke-width` and `font-size`. | Remove a `stroke` you did not want to see. |
| Default tooltip text uses the tooltip foreground; series colors move to swatches. Legend items contain native buttons. | Use `.v-charts-tooltip-swatch` for swatch styling and `.v-charts-legend-item button` for control styling. |
| Text on known opaque fills chooses black or white. Variable and translucent fills use `--v-charts-label-foreground`. BarList always tints its bar color. | Set and verify a foreground override for custom fills in both themes. Pass the base color to BarList instead of a pre-tinted color. |
| Bar `class` sits once on the series layer (`[data-slot=series].v-charts-bar`), not on every rectangle. Every series layer now gets its `class`; Scatter, Radar and RadialBar gain a `class` prop. | Before: `.my-bars { … }` matched each rect. After: `.my-bars .v-charts-bar-rectangle { … }`. |
| Pie, RadialBar and Funnel tooltip swatches show the entry color; Scatter swatches show the series fill. Before they were empty unless `fill` was set. | Read `color` and `fill` from the `#content` payload if you drew your own swatch. |
| The Pie legend uses `<Cell fill>`, and Funnel labels use the Cell fill instead of the palette or row color. | Nothing. Legend, tooltip, label and shape now agree. |
| `<Area stroke="none">` hides the outline; legend, tooltip and active dot then use the fill. The Area active dot uses the stroke color like its legend and tooltip swatch (it used the fill). | Set `stroke` to the color you want on the outline and the active dot. |

## Behavior changes (usually nothing to do)

| Change | What to do |
|---|---|
| Default animation timing is shared by all elements (0.6 s enter, 0.5 s update). Lines appear with a left-to-right sweep instead of drawing their stroke. | Pass `:transition` to keep a custom timing. |
| Charts follow a resize at once; only data changes animate. Axis ticks and grid lines now animate with the series. | Nothing. Set `:is-animation-active="false"` on the series to keep the whole chart still. |
| Series hidden from the legend animate out and back in instead of vanishing. | Nothing. |
| Legend entries and tooltip rows keep the data or series order; they were sorted by name. | Pass `item-sorter="value"` (Legend) or `item-sorter="name"` (Tooltip) to sort as before. |
| `Pie` respects `hide`. | Remove workarounds for a hidden pie that still rendered. |
| Generated SVG ids use Vue's `useId()`. | Do not select elements by generated ids; pass `id` to the chart if you need a stable one. |
| Non-finite values (`Infinity`, `NaN`) are treated as missing, and numeric strings (`"12"`) count as numbers in Pie, Funnel, Treemap and Sunburst. Sankey drops links to missing nodes and links that close a cycle (with a dev warning). | Nothing, unless you relied on the old output. |
| Brush travellers announce category indexes instead of pixel coordinates. | Use geometry attributes for positions; `aria-value*` describes the data range. |
| BarList height follows entering and leaving rows on the animation clock. | Reserve space on a parent if the surrounding layout must stay fixed. |
| YAxis now defaults `yAxisId` to `0`. | Before: `<YAxis :y-axis-id="0" />`. After: `<YAxis />`. Explicit ids still work. |
| `allowDataOverflow` on one axis clips only that axis (Line, Bar); Area now clips like Line. | Nothing. Before, both axes were clipped and Area never was. |
| `reverseStackOrder` works: `true` puts the last stacked item at the base (Recharts behavior). | Before, `true` and `false` drew the same stack. Remove the prop if you relied on that. |
| The chart `role` prop applies: it replaces `application` on the wrapper (with the accessibility layer) or `img` on the svg. | Nothing. Before, it was dropped on normal charts. |
| Funnel marks the hovered trapezoid active, as keyboard selection already did. In a ComposedChart, the Scatter point at the active axis index is enlarged. | Nothing. |
| Radar legend values and the Radar and RadialBar tooltip names use `name`, then a string `dataKey`. | Differs only for `name=0` or a function `dataKey`; set `name`. |
| Series tooltip entries carry `strokeWidth` from the series prop (Line default `1`); before it was always undefined. | Nothing. |
| PolarGrid polygon `d` strings drop the spaces (`M x,yL x,y` → `Mx,yLx,y`); the geometry is the same. | Update snapshot tests. |
| Numeric and string axis ids name the same axis (`y-axis-id="1"` and `:y-axis-id="1"`). | Nothing. Before, a mix created a second axis without series. |

## Standalone chart tooltips

Heatmap, CalendarHeatmap, CohortChart, Tracker, Sparkline, Sankey, Treemap and JourneySankey
now give the tooltip one payload shape, the same as cartesian charts: `payload` is the domain
object and `value` is the raw value. One `#content` template works for every chart.

| Change | What to do |
|---|---|
| `payload[0].payload` is the domain object: `HeatmapCell`, `CalendarDay`, `CohortCell`, the Tracker row, the Sparkline row, your Sankey or Treemap node or link, `JourneyNode` or `JourneyLink`. Before it was a wrapper `{ name, value, payload, color }` or an internal node with `tooltipIndex`. | Before: `payload[0].payload.payload.hour`. After: `payload[0].payload.rows` (a `HeatmapCell`), or the node itself for Sankey and Treemap. |
| `value` is the raw value: a number (the status for Tracker, the session count for Journey). Before Heatmap, CohortChart, Tracker and JourneySankey gave formatted text such as `'42%'`. | The default tooltip still shows the readable text. A Tooltip `formatter` now receives the raw value. |
| Heatmap and CalendarHeatmap value text uses the locale number format by default (`1,234` instead of `1234`), like CohortChart, Sparkline and BarList. | Nothing for small integers. To keep raw numbers, pass `:value-formatter="String"`; set `locale` to pick the format. |
| A Tooltip `formatter` wins over a chart's own default formatter. | Nothing. Before, a chart default could hide your formatter. |
| CohortChart's tooltip payload is `CohortCell`, the same object as its events and `#cell` slot. | Read `cell.period` and `cell.rows` as in events. |
| A Tracker day without status has value `null`, so the default tooltip hides it. Its `aria-label` still says "No data". | Set `filter-null` to `false` on the Tooltip to show it. |
| A Treemap parent node shows its real name and the sum of its leaves; before it showed `root` and its own field. | Nothing. |
| Sparkline bar-mode tooltips name points by `nameKey`, like line mode (before: `1`, `2`, …). | Nothing. |
| The Label `#content` slot receives the normalized `viewBox`: missing sizes and angles are `0`. | Nothing, unless you checked for `undefined`. |

## Accessible names and markup

| Before | After |
| --- | --- |
| `<Heatmap aria-label="Visits" />` (component prop `ariaLabel`) | `<Heatmap title="Visits" desc="Visits by hour" />` |
| Default name `BarChart chart` | Default name `Bar chart`; every chart supports `title` and `desc`. |
| `data-recharts-item-index`, `data-recharts-item-data-key` | `data-v-charts-item-index`, `data-v-charts-item-data-key` |

Style chart parts with `data-slot`: `chart`, `surface`, `plot`, `grid`, `x-axis`,
`y-axis`, `angle-axis`, `radius-axis`, `series`, `tooltip`, `legend`, `brush`, `cell`, and `label`.
Native `aria-*` attributes are still forwarded.

## Typed rows

| Before | After |
| --- | --- |
| `const { BarChart, Bar } = defineChartComponents<Row>()` | `const Chart = defineChartComponents<Row>()({ BarChart, Bar })`; render `<Chart.BarChart>` and `<Chart.Bar>`. |
| `<Heatmap x-key="unknownField" :data="hits" />` could typecheck | `<Heatmap x-key="hour" :data="hits" />`; keys and payloads infer from the row type in `data`. Nested paths and typed accessors remain supported. |
| `day.value` provides the aggregate | `day.value` still provides the aggregate; `day.rows` contains source rows and is empty for a missing day. |
| `cell.row` exposes an internal aggregation row | `cell.row` is the first contributing source row; `cell.rows` and `cell.period` retain provenance and the period. |
| `node.value` / `link.value` provide aggregate counts | `node.rows` / `link.rows` contain contributing source rows; layout fields and counts remain available. |
| `#shape="{ x }"` could receive `undefined` | `#shape="{ x }"` receives numeric geometry; missing geometry produces no shape or activeBar slot call. |

## Renamed props and events

| Change | Before | After |
| --- | --- | --- |
| Tooltip content prop | `<Tooltip :content="renderTooltip" />` | `<Tooltip><template #content="props">…</template></Tooltip>` |
| Tooltip default content slot | `<Tooltip><div>…</div></Tooltip>` | `<Tooltip><template #content><div>…</div></template></Tooltip>` |
| Tooltip teleport target | `<Tooltip :portal="element" />` | `<Tooltip :to="element" />`; a CSS selector also works. |
| Legend teleport target | `<Legend :portal="element" />` | `<Legend :to="element" />`; a CSS selector also works. |
| Tooltip transition type | `const transition: AnimationOptions = { duration: 0.2 }` | `const transition: ChartTransition = { duration: 0.2 }`; import the type from `vccs`. |
| Treemap palette | `<Treemap :color-panel="palette" />` | `<Treemap :colors="palette" />` |
| Treemap tile proportions | `<Treemap :aspect-ratio="1" />` | `<Treemap :tile-aspect-ratio="1" />`; `aspect` sets the chart's proportions. |
| Tracker status colors | `<Tracker :colors="colors" />` | `<Tracker :status-colors="colors" />` |
| Tracker status labels | `<Tracker :labels="labels" />` | `<Tracker :status-labels="labels" />` |
| Heatmap and BarList value text | `<Heatmap :value-format="formatValue" />` / `<BarList :value-format="formatValue" />` | `<Heatmap :value-formatter="formatValue" />` / `<BarList :value-formatter="formatValue" />` |
| Heatmap column labels | `<Heatmap :x-label-format="formatX" />` | `<Heatmap :x-tick-formatter="formatX" />` |
| Heatmap row labels | `<Heatmap :y-label-format="formatY" />` | `<Heatmap :y-tick-formatter="formatY" />` |
| Cohort period labels | `<CohortChart :period-label="formatPeriod" />` | `<CohortChart :period-formatter="formatPeriod" />` |
| Journey subtitles | `<JourneySankey :format-subtitle="formatSubtitle" />` | `<JourneySankey :subtitle-formatter="formatSubtitle" />` |
| ResponsiveContainer resize callback | `<ResponsiveContainer :on-resize="resize" />` | `<ResponsiveContainer @resize="resize" />` |
| Journey node and link click arguments | `function click(item, event) { … }` | `function click(item, index, event) { … }`; `index` is the position in the layout's node or link list. |

There are no aliases for renamed props. `ResponsiveContainer` and `Customized` remain in
1.0 and warn once per app in development. Replace a sizing wrapper with the chart's `width`,
`height` or `aspect`; replace `Customized` with the chart's default slot and `usePlotArea()`.
Both components are scheduled for removal in 2.0.

New customization options include Tooltip `labelFormatter`, Radar `#shape`, `#dot`,
`#activeDot` and `#label`, RadialBar `#shape` and `#label`, and CartesianGrid
`#horizontal` and `#vertical`. SunburstChart and JourneySankey add node hover events;
JourneySankey also adds link hover events. These additions do not require migration.
