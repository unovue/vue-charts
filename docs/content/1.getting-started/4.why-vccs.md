vccs suits Vue apps that want to build a chart from components and style it with CSS. It isn't the smallest option, and its speed with very large datasets isn't benchmarked here. The [comparison site](https://vue-charts-benchmark.crimson-dream-a1de.workers.dev) renders the same data in nine libraries side by side, with the code for each card, so you can judge for yourself.

## What vccs is good at

- **Components instead of a config object.** A chart is `<BarChart>`, `<Bar>`, `<XAxis>` and `<Tooltip>`, and you customize parts with slots. If you know Recharts, the API will feel familiar.
- **CSS theming.** Default colors come from CSS variables, so dark mode needs no chart code.
- **Server rendering.** Charts render as SVG on the server, and `vccs/nuxt` registers everything in Nuxt.
- **Keyboard and screen readers.** Charts have an accessible name, keyboard navigation and announcements.
- **Coding agents.** An official [skill](https://github.com/unovue/vue-charts/tree/main/skills/vccs-usage) gives your agent guides that match your installed version.
